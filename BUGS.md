# Bugs found by the e2e sweep

Each bug: where it was found, what happened vs what should happen, and the fix commit.

| # | Found by | Repo | Bug | Expected | Fix |
|---|---|---|---|---|---|
| B-01 | Harness design (DB reset while the API runs) | sg-api | `pg.Pool` had no `error` listener. When Postgres dropped an idle connection (restart, failover, admin kill), Node treated it as an unhandled `error` event and **the API process exited**. | API logs it, discards the connection and keeps serving. Verified by killing the API's DB connections with `pg_terminate_backend`. | `467c2a7` |
| B-02 | STU-03, TUT-14 (slow, 1.6–1.8 s) | sg-app, sg-backoffice | React Query retried every failed request, including 4xx, so "Class not found" or "forbidden" appeared about 1 s late. | 4xx shown immediately; only network/5xx errors are retried (once). | sg-app `6d731a4`, sg-backoffice `b8779f2` |
| B-03 | Running lint after the first e2e build | sg-app, sg-backoffice | ESLint linted the `.next-e2e` build output (6,000+ false problems). | Build output ignored. | sg-app `5b9d076`, sg-backoffice `0fcc7cb` |
| B-04 | SEC-08 | sg-api | A malformed JSON body (e.g. `{not json`) returned **500 "Something went wrong"**: `express.json()` parse errors fell through to the generic handler. Oversized bodies did the same. | 400 "The request body is not valid JSON"; 413 for bodies over 100 kB. Unit test added in sg-api. | `6e20cd9` |
| B-05 | UI-03 (axe) | sg-app, sg-backoffice | Text failed WCAG AA contrast: the brief's status colours as text (`#0AB848` 2.6:1, `#FF2819` 3.7:1), gold warning text, muted text on grey (4.2:1), inactive tabs, faded margin %. | ≥ 4.5:1 everywhere. Nearest passing shades of the brand colours are used for text; exact brand values kept as `--sg-*` tokens. | sg-backoffice `ee2e329`, sg-app `d477e0a` |
| B-06 | UI-03 (axe, **critical**) | sg-backoffice | Invoices/Lessons/Logbooks used Tabs as list filters without tab panels → `aria-controls` pointed at missing elements. | Filters are a labelled group of toggle buttons (`aria-pressed`). | `8cadfd0` |
| B-07 | UI-04 | sg-app, sg-backoffice | After closing a dialog with Esc, keyboard focus fell to `<body>` (dialogs are opened from code, so Radix had no trigger to return to). | Focus returns to the element that opened the dialog. | sg-backoffice `7d9c713`, sg-app `dab1e41` |
| B-08 | RES-01 | sg-backoffice (sg-app wording) | With the API unreachable the back office showed the raw browser error **"Failed to fetch"**; the app said "You're offline" even when only the server was down. | "Couldn't reach the server. Check your connection and try again." + working *Try again*. | sg-backoffice `e1f2bea`, sg-app `9fa87f2` |
| B-09 | RES-02 | sg-app, sg-backoffice | A fast double-click on Pay / Mark paid / Approve sent two requests. Data stayed correct (server rejects the second) but the user saw an **"already paid"** error. | One request per action; a synchronous lock (`useOnce`) on every action that changes data. | sg-app `b94c512`, sg-backoffice `362b952` |
| B-10 | Harness (UI-03 kept failing after a fix) | sg-e2e | Building both frontends in parallel from Playwright's `webServer` sometimes produced a **stale CSS bundle**, so a fixed bug still looked broken. | Builds run sequentially in `scripts/build-apps.mjs`; `global-setup.ts` refuses to test a build older than its source. | sg-e2e (this repo) |
| B-11 | Reported by user (Enroll modal) → UI-06 | sg-app, sg-backoffice | Long dialog titles ran under the absolutely-positioned close button (e.g. "Enroll in Cambridge Primary Checkpoint Science Grade 6?"); the header reserved no space for it. Overlap measured: title to x=378, ✕ from x=358. | Header keeps clear of the ✕ in every dialog. UI-06 measures both bounding boxes on Pixel 7, iPhone and the back office; verified it fails without the fix. | sg-app + sg-backoffice "fix: long dialog titles…" |
